# 双写定义

event_id唯一，doc_id文本保留。side为source或index；版本正整数按Decimal比较并作为文本序列化。upsert要求JSON对象，delete忽略payload并产生墓碑。相同文档同端同版本不同内容全部隔离，存在未裁决冲突的主体不回落旧版本；同内容合并来源；较高版本覆盖低版本，迟到旧写不得覆盖墓碑。

## 字段契约与准入

登记表在 `app/schemas.py`，一次批次只能按一个已登记版本解释。

| 版本 | 字段 | 说明 |
|---|---|---|
| v1 | 原始10列（见 `app/config.py`） | 原始固定字段，永远按此原义解释 |
| v2 | v1 + `category`、`tags` | 可检索属性，均为可选；属性也参与内容比较 |

裁决规则：

- 表头**恰好只有原始列** → v1。旧导出不会因为新版本上线而改变含义或批次身份。
- 表头多出列且全部是 v2 已登记属性 → v2。按表头**名字**对齐，不依赖列顺序，新段插入属性列不会让旧段错位。
- 表头出现**未登记字段** → 整段隔离（`UNDECLARED_FIELD`），原始行整行保留，不进入正式结果，也不按旧定义硬解释。
- 缺原始必填列（`MISSING_DECLARED_FIELD`）、表头重复列（`DUPLICATE_FIELD`）→ 整段隔离。
- 完全无法识别的表头（不含任何原始列名）→ 入口 422，不写批次，保持导入原子性。
- `parameters.schema_version` 可声明本批版本：声明 v2 时，只有原始列的旧段仍按 v1 原义读入，回补不因新旧混排停住；声明 v1 却出现扩展属性，或声明未登记版本（`SCHEMA_VERSION_CONFLICT`）→ 整段隔离。
- 一个批次可含多段表头，每段各自裁决；`contract.admission` 为 `FORMAL`（全部准入）、`PARTIAL`（有段隔离但有采纳行，采纳行照常回补）或 `QUARANTINED`（无采纳行，回补不就绪）。

同键在新旧导出中一起回放时，只比较双方共同声明过的字段：共同字段一致、仅多出已声明属性 → 补记属性并保留首条原值（`schema_enriched`）；共同字段取值冲突 → 隔离（`DUPLICATE_CONFLICT`）；完全相同 → 重复。

批次身份包含输入摘要、规则版本与参数；涉及扩展属性时还绑定本批实际用到的契约版本定义摘要。定义变更后重跑得到新批次，不复用或改写已封存的旧结论；只含原始列的旧导出身份不受新属性登记影响。

双端最终版本、操作、文档分别核验；扩展属性也计入内容比较，但只比较双方都声明过的属性。目标缺失、删除未确认、索引领先、陈旧索引、内容差异分开展示。source_time与visible_time带偏移；可见延迟按实际秒数。默认阈值120秒，等于阈值通过。已可见但超过阈值为延迟，尚无目标且等待时间超过阈值为缺失，等待中不冒充延迟。

对账expected=每文档应通过的1，reported=门禁通过1或未通过0，逐条保存visibility_state和gate原因，允许按文档复核。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、契约范围、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头、类型和版本声明返回422，失效版本复核返回409。
